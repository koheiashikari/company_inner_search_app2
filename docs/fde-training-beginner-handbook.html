2
集計スクリプトを書く

「部署ごとの人数を数えて、多い順に表示する」プログラムを作ります。まずは下のコードを写経して動かし、その後で1行ずつ意味を説明できるようにします。

aggregate.py 
import csv

# 1. CSVファイルを読み込む
with open("employees.csv", encoding="utf-8") as f:
    rows = list(csv.DictReader(f))

# 2. 部署ごとの人数を辞書で数える
counts = {}
for row in rows:
    dept = row["部署"]
    counts[dept] = counts.get(dept, 0) + 1

# 3. 人数が多い順に表示する
print(f"社員数合計: {len(rows)}名")
for dept, n in sorted(counts.items(), key=lambda x: x[1], reverse=True):
    print(f"  {dept}: {n}名")

集計結果が多い順に表示されれば成功。数字は配布データによって変わります。

第2章 Git・GitHub・ターミナル操作

チーム開発の共通言語。「ブランチ→コミット→プルリクエスト→レビュー対応→マージ」の一連の流れを、この週は毎日1回転させて体で覚えます。

🎯 この章の学習ゴール
  • ブランチを切って作業し、意味の通るメッセージでコミットできる
  • プルリクエスト(PR)を作成し、レビュー指摘に修正で応えてマージまで完走できる
  • git status / git diff / git log で「今リポジトリがどんな状態か」を自分で確認できる

第3章 SQLとデータモデリング基礎

FDEの仕事は「データに始まりデータに終わる」。教材リポジトリの data/ を元にしたサンプルDBを使い、データを取り出す言語=SQLを習得します。

🎯 この章の学習ゴール
  • SELECT / WHERE / JOIN / GROUP BY を使った問い合わせが自力で書ける
  • 「社員と部署を別テーブルに分けてIDでつなぐ」理由(正規化)を自分の言葉で説明できる
  • 日本語の質問(例:「部署ごとの平均勤続年数は?」)をSQLに翻訳できる

1

テーブルの構造(データモデル)を理解する

社員テーブルには部署の「名前」ではなく「部署ID」だけが入っています。部署の情報は部署テーブルに1回だけ書く——これが正規化(1つの事実は1か所にだけ書く)です。部署名が変わっても1か所直せば済みます。

3-2. 問い合わせ演習(基本 → 応用)

1
基本:絞り込んで取り出す(SELECT / WHERE)

「入社が2023年以降の社員の氏名と入社年」を取り出します。

SELECT name, hire_year
FROM employees
WHERE hire_year >= 2023;
2
応用:テーブルをつないで集計する(JOIN / GROUP BY)

「部署ごとの社員数を多い順に」。2つのテーブルを JOIN でつなぎ、GROUP BY でまとめて数えます。

SELECT d.dept_name, COUNT(*) AS members
FROM employees e
JOIN departments d ON e.dept_id = d.dept_id
GROUP BY d.dept_name
ORDER BY members DESC;
ターミナル — SQLite 実行結果

第1章でPythonで書いた集計と同じ結果を、SQLなら3行で取り出せます。「どちらの道具をいつ使うか」の感覚もここで養います。
3
演習課題(自力で書く)

次の日本語の質問をSQLに翻訳してください。答え合わせはメンターとのペア作業で行います。

  1. 「営業部の社員一覧を、入社年の古い順に」(JOIN + WHERE + ORDER BY)
  2. 「入社3年以内(2024年以降)で営業部の社員の氏名」(条件の組み合わせ)

  4. 「顧客ごとの契約サービス数」(customers と services のJOIN)
  5. 発展:「社員が1人もいない部署」(LEFT JOIN と IS NULL)
✅ 確認ポイント(第4週修了の条件)

  • 「なぜ社員テーブルに部署名を直接書かないのか」を後輩に説明するつもりで話せた

# 1. FAQデータを読み込む

# 3. キーワードで絞り込んで表示
if keyword:
    hit = df[df["質問"].str.contains(keyword) | df["回答"].str.contains(keyword)]

第16週仕上げ・リハーサル → 最終発表最終デモ+プレゼン15分・質疑10分(金曜)/ 振り返りシート(翌月曜)
💡 週次のメンター壁打ち(毎週火曜30分)は必ず使うこと。「順調です」で終わらせず、一番不安な点を1つ持ち込むのがルールです。

成果物合格の目安
