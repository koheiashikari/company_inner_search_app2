# FDE(Forward Deployed Engineer)実践研修プログラム

コンサルティング会社の社員向けに、レベル別(新卒・中途・未経験者)の FDE 育成研修を定義したドキュメントです。
本リポジトリの「社内情報検索アプリ」(Streamlit + LangChain + RAG)および Palantir OSDK オントロジー検証スクリプト(`test_parantia_ontology.py`)を、ハンズオン教材として活用します。

---

## 1. FDE とは / 研修のゴール

FDE(Forward Deployed Engineer)は、**顧客の現場に入り込み、技術力とコンサルティング力の両方を使って課題を解決するエンジニア**です。Palantir 社が確立した職種として知られ、以下の 3 領域のスキルが求められます。

| 領域 | 具体スキル |
|---|---|
| エンジニアリング | Python / SQL / Git / API 設計 / データパイプライン / LLM・RAG / クラウド基礎 |
| コンサルティング | 要件ヒアリング / 課題の構造化 / 提案資料作成 / ステークホルダー管理 / ファシリテーション |
| ドメイン・プロダクト | 顧客業界の業務知識 / 自社プロダクト・プラットフォーム(例: Palantir Foundry, 生成AI 基盤)の深い理解 |

**研修の共通ゴール:**
「顧客の曖昧な課題を聞き取り、データとソフトウェアで動くものを短期間で作り、現場に定着させられる」状態になること。

**修了判定の統一基準(全レベル共通の最終アウトプット):**
1. 顧客役へのヒアリングから要件定義書を作成できる
2. 本リポジトリ相当の RAG アプリを自力で改修・機能追加できる
3. 成果物を顧客役の前でデモ・プレゼンし、質疑に答えられる

---

## 2. 対象者のレベル定義

| 区分 | 想定プロフィール | 研修期間 |
|---|---|---|
| 未経験者 | プログラミング経験なし(営業・バックオフィス等からの転換組) | 16 週間 |
| 新卒 | 情報系または独学でプログラミング基礎あり。実務経験なし | 12 週間 |
| 中途 | エンジニアまたはコンサルタントとしての実務経験 3 年以上 | 6 週間 |

---

## 3. 未経験者向けプログラム(16 週間)

技術の土台作りに最も時間を割きます。「写経 → 模倣 → 自作」の 3 段階で進めます。

### フェーズ 1: エンジニアリング基礎(第 1〜6 週)

| 週 | テーマ | 実践課題 |
|---|---|---|
| 1-2 | Python 基礎(変数・制御構文・関数・クラス) | 演習問題 100 本ノック。CSV を読み込んで集計するスクリプト作成 |
| 3 | Git / GitHub / ターミナル操作 | ブランチ作成 → コミット → プルリクエスト → レビュー対応の一連の流れを毎日実施 |
| 4 | SQL とデータモデリング基礎 | サンプル DB(社員・顧客・サービスのデータ。`data/` フォルダを題材化)への問い合わせ演習 |
| 5-6 | Web アプリ基礎(HTTP / API / Streamlit) | Streamlit で簡単な社内 FAQ 表示アプリをゼロから作る |

### フェーズ 2: 生成 AI・RAG 入門(第 7〜10 週)

| 週 | テーマ | 実践課題 |
|---|---|---|
| 7 | LLM の仕組みとプロンプトエンジニアリング | OpenAI API を呼び出す最小スクリプト作成。プロンプト改善の比較実験 |
| 8 | RAG の概念(Embedding / ベクトル検索 / チャンク分割) | 本リポジトリの `initialize.py` を読解し、処理フローを図解して発表 |
| 9-10 | 本リポジトリのアプリを動かす・改修する | 環境構築 → 起動 → 「回答に参照元ページ番号を表示する」等の小改修を PR で提出 |

### フェーズ 3: コンサルティング基礎(第 11〜13 週)

| 週 | テーマ | 実践課題 |
|---|---|---|
| 11 | 課題の構造化(ロジックツリー / MECE) | 「社内の情報検索に時間がかかる」という課題を構造化しドキュメント化 |
| 12 | ヒアリングと要件定義 | 先輩社員が顧客役のロールプレイ。議事録と要件定義書を作成 |
| 13 | 資料作成とプレゼン | 要件定義の内容を経営層向け 5 枚スライドにまとめて発表 |

### フェーズ 4: 総合演習(第 14〜16 週)

- **課題:** 「架空の顧客(例: 製造業の人事部)の社内文書検索を効率化せよ」
- 顧客役へのヒアリング → 要件定義 → 本リポジトリをベースに機能追加(例: 部署別の検索フィルタ、CSV 社員名簿の横断検索)→ デモ・最終プレゼン
- メンター(中途研修修了者など)が週次でコードレビューと壁打ちを実施

## 4. 新卒向けプログラム(12 週間)

プログラミング基礎は習得済みの前提で、**実務レベルの開発プラクティスとコンサルスキルの比重を高めます**。

### フェーズ 1: 実務エンジニアリング(第 1〜4 週)

| 週 | テーマ | 実践課題 |
|---|---|---|
| 1 | 開発環境・チーム開発の作法 | 本リポジトリを clone し、Issue 起票 → ブランチ → PR → レビューのサイクルを体験 |
| 2 | コードリーディング | `main.py` / `initialize.py` / `utils.py` / `components.py` の責務分離を読み解き、アーキテクチャ図を作成して発表 |
| 3 | テストとログ・エラーハンドリング | `test_parantia_ontology.py` を参考に、`utils.py` の関数へ pytest のテストを追加。ログ設計をレビュー |
| 4 | RAG の内部理解 | チャンクサイズ・Embedding モデル・検索件数(top-k)を変えて回答品質を比較し、評価レポートを作成 |

### フェーズ 2: プロダクト・プラットフォーム研修(第 5〜7 週)

| 週 | テーマ | 実践課題 |
|---|---|---|
| 5 | データ基盤とオントロジー概念 | Palantir Foundry 等のプラットフォーム概説。`test_parantia_ontology.py` を題材に OSDK / オントロジー(Object / Link / Action)の構造を学習 |
| 6 | データパイプライン演習 | `data/` 配下の雑多なファイル(PDF / DOCX / CSV / MTG 議事録)を構造化データに変換するパイプラインを実装 |
| 7 | クラウドデプロイ基礎 | アプリを Streamlit Cloud 等にデプロイし、環境変数・シークレット管理を実践 |

### フェーズ 3: コンサルティング実践(第 8〜9 週)

- 顧客ロールプレイ(要件が曖昧・途中で変わる設定)でのヒアリング → 要件定義 → スコープ交渉
- 「技術的にできること」と「顧客が本当に必要なこと」のギャップを埋める提案書の作成
- 先輩 FDE の商談・定例への同席(シャドーイング)を週 2 回以上

### フェーズ 4: 模擬プロジェクト(第 10〜12 週)

- 3〜4 名のチームで、実在の社内課題(例: 営業部の過去提案書検索)を題材にした開発
- 週次で顧客役(マネージャー)への進捗報告・デモを行い、フィードバックを反映
- 最終週: 成果発表会 + 個人ごとの振り返り(360 度フィードバック)

## 5. 中途向けプログラム(6 週間)

既存スキルを前提に、**「自社のやり方」と「不足領域の補完」に絞った短期集中型**です。初週にスキルアセスメントを行い、エンジニア出身/コンサル出身で重点を変えます。

### 第 1 週: アセスメントとオンボーディング

- コーディングテスト + ケース面接形式のアセスメントで不足領域を特定
- 本リポジトリの環境構築 → 起動 → 小改修 PR を初週中に提出(開発フローの習熟確認)

### 第 2〜3 週: 出身別ブリッジ研修

| 出身 | 重点内容 |
|---|---|
| エンジニア出身 | 課題構造化・提案書作成・顧客折衝のロールプレイ集中訓練。価格/スコープ交渉の模擬演習 |
| コンサル出身 | Python / Git / RAG 実装のブートキャンプ。本リポジトリへの機能追加(例: 会話履歴の永続化、検索精度改善)を毎週 1 本 PR 提出 |

共通: 自社プロダクト・過去案件事例のケーススタディ(成功案件・炎上案件の両方)

### 第 4〜5 週: OJT 型実案件シャドーイング

- 実案件に「準メンバー」としてアサインし、議事録作成・小タスクの実装を担当
- 週次でメンター FDE との 1on1(案件での動き方・顧客とのコミュニケーションのレビュー)

### 第 6 週: 独り立ち判定

- 実案件の 1 テーマを単独で担当し、顧客(または顧客役)向けにデモ・報告
- 判定基準: 要件把握の正確さ / 実装品質 / 説明の分かりやすさ / 期日管理

---

## 6. 共通の運営設計

### 評価とレベル判定

- 各フェーズ末にルーブリック評価(技術 / コンサル / ドメインの 3 軸 × 5 段階)
- 成果物(PR、要件定義書、プレゼン)はすべてポートフォリオとして蓄積し、アサイン判断に利用

### メンター制度

- 受講者 2〜3 名に対しメンター FDE 1 名。週 1 の 1on1 + PR レビュー
- 中途修了者が次期の未経験者・新卒のメンターを務める「教えることで定着させる」サイクル

### 教材としての本リポジトリの使い方(まとめ)

| 教材 | 用途 |
|---|---|
| `main.py` / `initialize.py` / `components.py` / `utils.py` / `constants.py` | コードリーディング、責務分離・設定管理の学習、改修課題のベース |
| `data/`(社員・顧客・サービス・MTG 議事録) | データパイプライン演習、RAG の検索品質評価の題材 |
| `test_parantia_ontology.py` | テストの書き方、Palantir OSDK / オントロジー概念の学習 |
| `requirements_mac.txt` / `requirements_windows.txt` | OS 別の環境構築演習 |

### 卒業後のフォロー

- 修了後 3 ヶ月間は月 1 回のフォローアップ会(案件での詰まりを共有)
- 研修課題・模範解答は本リポジトリのブランチとして蓄積し、次期研修で再利用
