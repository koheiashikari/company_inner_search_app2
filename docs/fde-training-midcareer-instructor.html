講師の役割と運営原則

  • 相手は経験3年以上のプロです。「教える」より「当社の基準を示し、差分を一緒に埋める」スタンスで。前職流のやり方には敬意を払いつつ、当社ルールの「理由」を必ず説明します。
  • 経験者特有のリスクは2つ:①プライドによる質問回避(詰まりを隠す)②前職の型の過剰適用。1on1で「今週、前職とやり方が違って戸惑った点」を定例質問にすると両方を検知できます。
  • アセスメント(第1章)の結果は選別ではなく処方箋。本人への開示は必ず「強み → 補強点 → プラン」の順で。

第 1 週

第1章 アセスメント — 実施要領と模範解答

3種目(コーディング/ケース面接/模擬レビュー)の実施ガイドです。評価のブレを防ぐため、必ず2名で採点し独立に点を付けてから突き合わせてください。

1-1. コーディングテストの課題と模範解答

✎ 出題(90分中40分)と模範解答

課題:「売上明細CSV(日付, 顧客名, 商品, 金額)を読み込み、顧客ごとの合計金額を高い順に出力せよ。ただし金額欄には『1,200円』『(空欄)』などの汚れが混ざっている」

import csv

def parse_amount(raw):
    # 「1,200円」「 1200 」等を整数化。空欄・解釈不能は None を返して呼び出し側で集計
    cleaned = raw.replace(",", "").replace("円", "").strip()
    if not cleaned:
        return None
    try:
        return int(cleaned)
    except ValueError:
        return None

totals, skipped = {}, []
with open("sales.csv", encoding="utf-8") as f:
    for i, row in enumerate(csv.DictReader(f), start=2):
        amount = parse_amount(row["金額"])
        if amount is None:
            skipped.append(i)          # 汚れ行は握りつぶさず記録
            continue
        totals[row["顧客名"]] = totals.get(row["顧客名"], 0) + amount

for name, total in sorted(totals.items(), key=lambda x: x[1], reverse=True):
    print(f"{name}: {total:,}円")
if skipped:
    print(f"※ 金額を解釈できず除外した行: {skipped}")
採点観点(各5点)満点の状態
正しく動く汚れデータでも落ちず、集計が正しい
汚れの扱い除外・補正の方針を自分で決めて明示している(黙って捨てない)
可読性関数分割・命名が適切(parse_amount の切り出し等)
口頭説明「なぜ None 方式にしたか」「行番号を2始まりにした理由」等の設計判断を語れる

1-2. ケース面接の評価ガイド

✎ お題「社内の問い合わせ対応が回らない(中堅製造業)」— 面接官用
  • 高評価の質問例:「問い合わせは誰から誰に、月何件来ていますか」「多い問い合わせ上位3つは」「回らないと、業務に何が起きていますか」— 事実・定量・影響を確認しに行く
  • 低評価のサイン:開始5分以内に「チャットボットを入れましょう」等の解決策を提示/仮説なしに質問を乱発/「AIで解決できます」と手段が先行
  • 揺さぶり(全員に1回):「で、結局いくらかかるの?」— 期待対応は「概算の前提を作るための逆質問」または「持ち帰りの宣言+期日」。適当な金額の即答は減点

仕込み気づけたら

第 2〜3 週(エンジニア出身)

第2章 ブリッジ研修(コンサル力)— 演技ガイドと模範解答

受講者用教材に掲載した「予算2割減」カード以外の、残り2枚のシナリオカードを収録します。ロールプレイは1日1カード・録画必須です。

交渉ロールプレイ:追加シナリオカード

✎ カード②「納期半減」(受講者には非公開)
顧客役の要求「役員会が前倒しになった。2週間の計画を1週間にできない?」
期待する対応例スコープの段階分割を返す:「1週間で『人事部の主要50文書のみ・検索と参照元表示まで』は出せます。残り(全文書・説明会)は役員会後の第2週に。役員会でお見せしたいのはどの部分ですか?」— 目的(役員会で何を見せたいか)を聞き返せたら加点
NG対応「徹夜すれば…」等の根性論/品質・テストを黙って削る(削るなら明示的に合意を取るのが正解)
✎ カード③「他社比較」(受講者には非公開)
顧客役の要求「他社は同じものを半額でやると言っている。おたくは高くない?」
期待する対応例価格でなく前提の differences を確認:「その内容、対象文書数と定着支援の範囲を伺えますか。当社の見積りには導入後1ヶ月の利用定着支援が含まれており、そこが御社の課題(使われないシステムの回避)に直結すると考えています」— 値引きせず価値軸に戻す
NG対応他社の悪口/根拠のないその場値引き/「では失注でも仕方ないです」と早々に降りる

「翻訳」トレーニングの模範解答(受講者記入欄の解答例)

✎ 追加3行の解答例(前職頻出用語)
エンジニアの言葉顧客の言葉への翻訳例
「ステージング環境で検証してから本番反映します」「本番と同じ条件の練習場で試してから、皆さんの環境に反映します。万一の不具合が業務に及ばない進め方です」

第 2〜3 週(コンサル出身)

第3章 ブリッジ研修(実装力)— PR課題の模範解答

ブートキャンプの解答は未経験者コース講師ガイドを流用してください。ここでは中途固有のPR課題②③の模範解答を示します。

PR課題②「会話履歴の永続化」の模範解答(組み込み側)

✎ 模範解答:chat_log.py(教材掲載)に加えた、アプリへの組み込み
# --- initialize.py: 表示用メッセージ初期化部の変更 ---
# 変更前: st.session_state.messages = []
import chat_log
if "messages" not in st.session_state:
    st.session_state.messages = chat_log.load_history()   # 前回分を復元
    if st.session_state.messages:
        st.session_state.restored = True   # 「復元しました」表示用のフラグ

# --- main.py: 回答表示後に保存を追加 ---
st.session_state.messages.append({"role": "assistant", "content": answer_text})
chat_log.save_history(st.session_state.messages)          # 送受信のたびに上書き保存

# --- components.py: サイドバーにクリアボタン(発展課題) ---
if st.button("🗑 会話履歴をクリア"):
    st.session_state.messages = []
    chat_log.save_history([])
    st.rerun()

レビューの要点:①保存するのは表示用テキストのみ(LangChainのメッセージオブジェクトをそのままJSON化しようとして詰まるのが最頻出。「表示用」と「LLM文脈用」の2つの履歴の区別に気づかせる)②logs/ を .gitignore に追加したか(会話ログのコミットは情報漏えい)③初回起動(ファイルなし)で壊れないか。

PR課題③「検索精度の改善」の模範解答(結論の書き方)

✎ 「顧客への説明」形式の模範例

「検索の設定を3案比較した結果、現行設定から検索件数のみ5→7に変更することを推奨します。効果は『複数部署にまたがる質問』の正答が10問中6→8問に改善すること、代償は回答が平均2秒遅くなることです。日常の単純な質問には影響がありません。来月データが増えた時点で再測定します。」

評価基準:効果とトレードオフが顧客の言葉で両方書かれているか/再測定の計画(運用視点)があるか。数値がなく「良くなった気がします」は差し戻し。

第 2〜3 週(共通・毎夕)

第4章 ケーススタディ — ファシリテーションガイド

講師は司会に徹し、結論を先に言わないこと。登壇する当時の担当FDEには「失敗も含めて話す」ことを事前に合意しておきます。

✎ 討議の問いかけ台本(2日目・60分)
  1. (冒頭10分)「分析シートの『最初の兆候』、全員の答えを並べます」— 兆候の位置が人によって違うことを見せる
  2. (20分)「その兆候の時点で、あなたが担当FDEなら明日の朝一番に何をしますか」— 抽象論を禁止し、行動レベルで言わせる
  3. (20分)当時の担当FDEへの質疑。講師から必ず1問:「当時、兆候に気づいていましたか。気づいていたのに動けなかったとしたら、何が止めましたか」— 構造(納期プレッシャー・言い出しにくさ)の話に到達させる
  4. (10分)「自分の前職で似た構造を見たことは?」— 経験者ならではの接続で締める

炎上案件の討議が「担当者の力量不足」という結論に流れたら必ず介入:「同じ人が成功案件も担当しています。差は人ではなく何でしたか?」

第 4〜5 週

第5章 実案件シャドーイング — 受け入れ運営

この2週間の成否は受け入れ側(担当FDE)の準備で決まります。講師(研修事務局)は受け入れ側との調整が主業務になります。

✎ 受け入れFDEへの依頼チェックリスト(アサイン確定時に送付)
  • ☐ 顧客に「研修中のメンバーが準メンバーとして参加します」と事前合意を取る
  • ☐ 受講者用の切り出しタスクを2週間で3〜4件用意(1件=2日以内・失敗しても案件が止まらないもの)
  • ☐ 議事録は「受講者が書く → あなたが確認 → 顧客送付」のフローを初回に説明する
  • ☐ 会議前30秒の「今日の見どころ」共有と、会議後5分の答え合わせに協力する
  • ☐ 週次で講師に一言共有(様子・気になる点)。評価は講師でなく現場の実感を最優先します

議事録の品質チェック基準(講師・受け入れFDE共通)

観点合格差し戻し
宿題の明確さ誰が・何を・いつまでに、が全宿題に揃っている「検討する」で終わる項目がある(誰が?いつ?)
速度会議当日中に確認依頼が来る翌日以降(記憶が薄れ、確認負荷が上がる)
要約力決定と発言が区別されている発言の書き起こしになっている

第 6 週

第6章 独り立ち判定 — 判定会議の運営

判定は「合格させるための儀式」ではありません。基準未達のまま送り出すと、本人と顧客の両方が不幸になります。迷ったら補習に倒してください。

判定会議の進め方(金曜の報告会後、60分)

  1. 出席:メンター講師・受け入れ担当FDE・研修事務局の3者。採点は会議前に各自独立で記入(4項目×3段階、受講者用教材に掲載の基準を使用)
  2. 点差が出た項目だけ議論する(全項目をなめ直さない)。「事実(何を見たか)→ 評価」の順で話す
  3. 合格(全項目2点以上):正式アサイン先と、最初の3ヶ月のフォロー担当を即決定
  4. 1項目でも1点:該当領域の補習プラン(下表)を作成し、1〜2週間後にその項目のみ再判定
✎ ボーダー事例の判断例(過去の判定より)
事例判定と理由
実装は完璧だが、完了条件を文書確認せず着手し、報告相手を間違えた補習。「要件把握」は独り立ちの生命線。技術力では代替できない
実装で1日遅延したが、火曜時点でリスクを報告しスコープ調整を自ら提案した合格。遅延そのものより「早期報告と調整」ができることが基準(期日管理=3点の行動)
デモは見事だが、質疑で不明点を推測で即答した(後で誤りと判明)補習。顧客の前での「誠実な持ち帰り」ができないのは事故リスク。ロールプレイ集中補習1週間

補習プランの標準メニュー

未達項目補習内容(1〜2週間)
要件把握着手前確認のチェックリスト運用+切り出しタスク2件で再訓練
実装品質未経験者/新卒コース教材の該当章+レビュー観点の写経(良いPRを3本読む)
説明の分かりやすさ第2章の交渉ロールプレイを毎日1本(録画必須)
期日管理日次の見積り・実績記録+「危険信号を出す練習」をメンター同席で
📎 修了後の運用:修了者は次期研修(未経験者・新卒コース)のメンター候補に登録します。メンター初回は本ガイドと各コース講師用ガイドを引き継ぎ、シニアFDEがメンターのメンターとして1ヶ月伴走してください。
