技術はある。足りないのは「顧客の言葉で考え、話し、交渉する」力。2週間、実装から離れてロールプレイ漬けになります。

  • 価格・スコープ交渉で、安請け合いせず選択肢を提示して着地できる

3-2. 週次PR課題②:会話履歴の永続化

教材アプリは再起動すると会話履歴が消えます(st.session_state はアプリを閉じると消えるため)。履歴をファイルに保存し、次回起動時に復元する機能を追加します。

1
現状の仕組みを確認する

会話履歴が st.session_state.chat_history にどう積まれるかを utils.py の get_llm_response() で確認します(履歴に追記している行を探す)。

2
保存・復元を実装する
実装の骨格(chat_log.py として追加) 
import json
from pathlib import Path

LOG_FILE = Path("logs/chat_log.json")

def save_history(messages):
    # 表示用の会話履歴(役割とテキスト)をJSONで保存
    LOG_FILE.parent.mkdir(exist_ok=True)
    LOG_FILE.write_text(json.dumps(messages, ensure_ascii=False, indent=2), encoding="utf-8")

def load_history():
    # ファイルがなければ空の履歴から開始(初回起動でも壊れない)
    if LOG_FILE.exists():
        return json.loads(LOG_FILE.read_text(encoding="utf-8"))
    return []

これを initialize.py(起動時に load_history())と main.py(送受信後に save_history())に組み込みます。

3
動作確認 → PR提出

①質問する → ②アプリを再起動する → ③履歴が画面に復元されている、をスクリーンショット付きでPRに記載します。発展:履歴のクリアボタン(st.button)も追加。

第 2〜3 週(全員共通・毎夕1時間)

第4章 ケーススタディ:成功案件と炎上案件

自社の過去案件(匿名化済み)を教材に、「何をすると成功し、何をすると燃えるか」を先に学びます。成功案件2本・炎上案件2本を扱います。

🎯 この章の学習ゴール
  • 炎上の兆候(スコープ曖昧・キーマン不在・定着軽視)を初期に嗅ぎ分ける観点を持つ
  • 自分ならどの時点で何をしたかを、案件資料を根拠に議論できる

進め方(1案件=2日)

1
1日目:資料読解と分析シート作成

提案書・議事録・振り返り資料(匿名化済み)を読み、下の分析シートを各自で埋めます。

2
2日目:討議 → 当時の担当者に質疑

受講者同士で「転換点はどこか」を討議した後、実際の担当FDEが登壇し質疑応答。資料に残らない話(顧客との空気、社内の判断)こそメモします。

ケース分析シート(炎上案件の記入例・抜粋)
案件:X社 文書管理システム導入(20xx年・匿名化済み)| 分析者:受講者
結果はどうだったか納期2ヶ月遅延・追加費用発生・利用率は導入3ヶ月で12%に低迷
最初の兆候はどこか要件定義書に「やらないこと」の記載がなく、キックオフ後も機能要望が増え続けた(議事録第3回から「あわせて〜もお願いしたい」が頻出)
転換点はどこだったか第5回定例。工数超過が明らかだったのに「なんとかします」と回答し、スコープ再交渉の機会を逃した
自分ならどうしたか第3回時点で要望を「今回/次回/対象外」に仕分ける場を設定し、経営層スポンサーに優先順位の判断を仰いだ
定着の観点での学び現場ユーザーが要件定義に一度も参加していない。導入後に使われないのは必然だった
分析シートの記入例。「犯人探し」ではなく「兆候と転換点の特定」が目的。炎上案件の担当者が語る会は本コースで最も評価の高いプログラムです。

第 4〜5 週

第5章 実案件シャドーイング(OJT)

実案件に「準メンバー」としてアサインされ、議事録作成と小タスクの実装を実際に担当します。研修と実務の境界を越える2週間です。

🎯 この章の学習ゴール
  • 実案件のリズム(定例・宿題・報告)に入り、小さな価値を実際に届ける
  • 担当FDEの判断(何を即答し、何を持ち帰るか)を観察し、自分の型に取り込む

5-1. 準メンバーとしての役割と約束事

やること約束事
定例会議の議事録作成会議終了後当日中に提出。決定事項と宿題(誰が・何を・いつまでに)を冒頭に書く。担当FDEの確認後に顧客へ送付
小タスクの実装(週1〜2件)担当FDEが切り出したIssueを担当。納期に間に合わない兆候は前日ではなく気づいた瞬間に報告
顧客との会話第4週は原則発言なし(観察)。第5週から担当FDE同席のもとで一部説明を担当

5-2. 週次1on1の使い方

1
1on1シートを事前に埋めて臨む(毎週金曜30分)

「今週の動きで一番迷った場面」を必ず1つ持ち込みます。うまくいった報告だけの1on1は時間の無駄です。

週次1on1シート(記入例)
受講者:佐々木 | メンター:田中 | 第4週金曜
今週やったこと定例議事録2本/検索フィルタ改修Issue #52 実装(レビュー1往復でマージ)
一番迷った場面顧客が定例で「別部署にも見せたい」と発言。その場で答えるべきか黙るべきか迷い、結局何も言えなかった
メンターの助言(記録)準メンバー期間は「持ち帰り」が正解。ただし沈黙ではなく「確認して明日ご連絡します」と自分の口で言えるとよい。次回同じ場面が来たら言ってみる
来週の実験定例で最低1回、宿題の引き取り発言を自分がする
1on1シートの記入例。「来週の実験」を毎回1つ決めるのがルール。小さな行動変化を毎週積むことが独り立ちへの最短ルートです。
✅ 確認ポイント(第4〜5週修了の条件)
  • 議事録が顧客送付品質(担当FDEの修正がほぼ不要)になった
  • 実案件のIssueを2件以上、レビュー2往復以内でマージした
  • 1on1で決めた「実験」を毎週実行し、結果を記録した

第 6 週

第6章 独り立ち判定

実案件の1テーマを単独で担当し、顧客(または顧客役)向けにデモ・報告を行います。合格すれば正式アサイン。この1週間はメンターは「聞かれたら答える」立場に退きます。

🎯 判定課題
  • 担当FDEから実案件の1テーマ(例:「検索対象への新データ追加と精度確認」)を引き継ぎ、要件確認 → 実装 → デモ・報告までを単独で完遂する
  • 金曜に顧客(または顧客役)向けの報告会(デモ15分+質疑10分)を実施する

6-1. 1週間の進め方

曜日やること
月テーマの引き継ぎ。着手前に「完了条件と報告相手」を文書で確認(ここの精度が判定の3割)
火〜木実装・検証。日次で進捗をタスクボードに更新(報告を求められる前に見える化)
金デモ・報告会 → その場で判定フィードバック

6-2. 判定基準(4項目×3段階)

項目合格(2点)優秀(3点)
要件把握の正確さ完了条件を文書で確認してから着手した暗黙の期待(報告形式・関係者)まで先回りして確認した
実装品質レビュー指摘が軽微でマージできる。動作確認手順が書かれている異常系への配慮とテストがあり、次の担当者への引き継ぎメモまである
説明の分かりやすさ技術に詳しくない相手に伝わるデモができた質疑で「分からないことの誠実な持ち帰り」と「即答」を適切に使い分けた
期日管理期日どおり、または遅延を早期に報告し調整したリスクを火曜時点で先出しし、スコープ調整を自ら提案した

合格ライン:全項目2点以上(合計8点以上)。1項目でも1点があれば、該当領域の補習(1〜2週間)後に再判定します。

✅ 修了後のみなさんへ
  • 正式アサイン後も3ヶ月間、月1回のフォローアップ会に参加します
  • 次期研修のメンターを担当します。未経験者・新卒コースのメンター経験は、FDEの説明力・伴走力の最良のトレーニングです(「教えることで定着させる」サイクル)
  • 本コースで作った成果物(PR・提案書・分析シート)はポートフォリオとして蓄積され、アサイン判断に活用されます
